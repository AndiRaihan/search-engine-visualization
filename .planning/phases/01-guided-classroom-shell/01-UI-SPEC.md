# Phase 1 - UI Design Contract

> Visual and interaction contract for the Guided Classroom Shell. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design Intent

Build a bright instructional debugging workspace for a fixed desktop/projector viewport. The interface must make the lesson sequence obvious from a distance: editable source material on the left, the current teaching step in the center, and the largest visual workspace on the right.

The shell is functional rather than decorative. Use clear borders, large labels, short explanatory copy, and restrained color. Do not use gradients, glass effects, dark mode, playful game styling, or independently scrolling panels.

**Source:** `01-CONTEXT.md` D-01 through D-04 and `docs/PRD.md` sections 9, 14, and 22.

### Vite-Compatible Initialization

Phase 1 must remain a Vite 8 React TypeScript SPA. The supplied `--template next` command is not valid for this project and must not be executed.

1. Create or retain the Vite React TypeScript scaffold.
2. Configure Tailwind through `@tailwindcss/vite`.
3. Add the `@/*` alias to `tsconfig.json`, `tsconfig.app.json` as required by the scaffold, and `vite.config.ts`, resolving `@` to `./src`.
4. From the existing Vite project root, apply the design preset with:

   ```bash
   npx shadcn@latest init --preset b1sAmVzcG
   ```

5. Verify generated `components.json` uses `"rsc": false`, `"tsx": true`, CSS variables, Lucide icons, and aliases rooted under `@/`.
6. Keep the Tailwind CSS entrypoint under `src/`; do not introduce Next.js folders, React Server Components, routing, server actions, or server-only dependencies.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps and compact inline separation |
| sm | 8px | Related controls, badge padding, field label gaps |
| md | 16px | Card internals, panel grid gap, control groups |
| lg | 24px | Panel padding and page horizontal padding |
| xl | 32px | Major groups within a panel |
| 2xl | 48px | Page header separation and lesson section breaks |
| 3xl | 64px | Reserved page-level separation; use at most once per view |

Exceptions:

- Interactive controls have a minimum height of 44px.
- Textareas start at 88px and auto-grow to 160px; after 160px the textarea scrolls internally.
- The progress bar track is 8px high.
- Focus rings are 4px wide with a 4px offset.

## Typography

Use exactly four sizes and two weights across Phase 1.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label and supporting text | 14px | 700 | 1.4 |
| Body and controls | 16px | 400 | 1.5 |
| Section heading and step title | 20px | 700 | 1.3 |
| Page title and visualization headline | 32px | 700 | 1.2 |

Rules:

- Body copy is limited to 65 characters per line where practical.
- Buttons use 16px/700 text; disabled labels remain readable.
- Do not use weights other than 400 and 700.
- Do not use all caps for headings. Small status badges may use sentence case only.
- Numeric step labels use tabular numerals.

## Color

The preset is the component basis, but the final CSS variables must resolve to these projector-safe values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F7F4` | Page background and open workspace |
| Secondary (30%) | `#FFFFFF` | Panels, cards, dialog, inputs, and visualization surface |
| Accent (10%) | `#087F8C` | Primary CTA, active progress fill, selected scenario indicator, and focus ring |
| Destructive | `#B42318` | Confirm-reset action and destructive icon/text only |

Supporting tokens:

| Token | Value | Usage |
|-------|-------|-------|
| Primary text | `#17212B` | Headings and body text |
| Muted text | `#465766` | Supporting explanations and metadata |
| Border | `#AAB7BE` | Panel, card, field, and divider boundaries |
| Subtle surface | `#E7EEF0` | Center-panel teaching callouts and disabled-control background |
| Accent contrast | `#FFFFFF` | Text and icons on accent fill |
| Destructive surface | `#FDECEA` | Reset confirmation warning area |

Accent is reserved for:

- `Start Search`
- the enabled primary forward action
- selected scenario marker plus its visible `Selected` label
- completed portion of the progress bar
- keyboard focus ring

Do not apply accent to every heading, card border, icon, or link. State must always include text, icon, shape, or position in addition to color. Body and muted text must meet WCAG AA contrast against their surfaces.

## Layout Contract

### Page Frame

- Supported design viewport: 1280px wide or larger desktop/projector display.
- Page uses one vertical document scroll. Panels must not have independent vertical scroll containers.
- Page padding is 24px; maximum content width is 1600px and centered.
- Header sits above the panel grid and contains the product title plus a one-sentence learning purpose.

### Three-Panel Grid

Use a 28% / 24% / 48% visual ratio with a 16px gap:

```css
grid-template-columns:
  minmax(300px, 28fr)
  minmax(280px, 24fr)
  minmax(480px, 48fr);
```

- Left: scenario, query, documents, panel-level edited state, reset.
- Center: current step, explanation, progress, Previous/Next controls.
- Right: current visualization or registered-step placeholder.
- All panels align at the top. Do not force equal heights.
- Panel surface is white with a 1px border, 12px radius, and no drop shadow. The right panel may use a 2px top border in the accent color to establish focus without tinting the full panel.

### Left Panel

- Order: `Scenario`, `Query`, `Documents`, edited/reset row.
- Scenario selector occupies full width and shows scenario title plus learning goal.
- Documents render as numbered cards from the scenario array using stable IDs.
- Each document card shows `Document {n}` and its textarea. No add/remove controls appear.
- The panel-level `Edited` badge is visible only after query or document text differs from scenario defaults.

### Center Panel

- Top order: eyebrow `Step {current} of {total}`, step title, short explanation, progress bar.
- Explanations answer `What did the search engine do?` and `Why does it matter?` in two short blocks.
- Navigation remains at the bottom of the panel content and stays visible in normal page flow.
- Before the simulation starts, `Start Search` is the single emphasized action. After starting, `Previous` and `Next` share the navigation row.

### Right Panel

- This is always the widest and visually strongest panel.
- Phase 1 placeholders show the registered step title, one-sentence preview, and a labeled diagram frame rather than blank space.
- Setup state heading: `Your search workspace`.
- Setup state body: `Choose a scenario, review the query and documents, then start the search.`

## Interaction Contract

### Scenario Switching

- Selecting a scenario applies immediately with no confirmation.
- It discards edits from the previous scenario, restores the new scenario defaults, and returns to setup.
- After selection, move focus to the setup step heading and announce the change through a polite live region: `{Scenario title} loaded. Query and documents restored.`

### Editing

- Query and document fields are controlled inputs.
- Textareas auto-grow from 88px to 160px without page jumps.
- Dirty state is derived, not manually toggled per field.
- Show one `Edited` badge beside `Reset scenario`; do not add changed markers to every field.

### Start and Navigation

- `Start Search` moves directly from setup to the first registered lesson step.
- `Previous` and `Next` navigate sequentially only. Progress indicators are not clickable.
- Previous remains visible and disabled at the first reachable boundary.
- Next remains visible and disabled at the final registered boundary.
- Disabled buttons use explicit visible labels and `disabled`; do not hide them.
- After step navigation, focus the new step heading without scrolling the page back to the top.

### Progress

- Show `Step {n} of {total}`, the current step title, and a progress bar.
- The progress component exposes `aria-valuemin="1"`, `aria-valuemax="{total}"`, `aria-valuenow="{n}"`, and an accessible label.
- Setup is a real registered position. The progress calculation must remain stable when later phases replace placeholders or insert registered steps.

### Reset

- If the current query and documents match defaults, Reset executes immediately.
- If either has been edited, open an alert dialog.
- Initial dialog focus is `Keep edits`.
- `Reset scenario` restores query, documents, vectors, selected-scenario defaults, and setup position.
- After reset, focus the query field and announce `Scenario reset to its original values.`

### Keyboard and Focus

- Native Tab/Shift+Tab order follows visual order: header, left panel, center panel, right panel.
- Enter/Space activates buttons and Select according to native component behavior.
- Escape closes the reset dialog and returns focus to the Reset button.
- All interactive controls show the 4px accent focus ring with a 4px offset. Never remove outlines without an equivalent.
- Phase 1 does not define global Previous/Next shortcuts; those belong to FLOW-06 in Phase 5.

### Motion

- Use a single 160ms opacity transition when placeholder content changes.
- Do not animate layout, panel position, progress width with spring physics, or textarea height.
- Under `prefers-reduced-motion: reduce`, remove the content transition.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Product title | `Search Engine Lab` |
| Product purpose | `See how a query becomes a ranked list, one step at a time.` |
| Primary CTA | `Start Search` |
| Previous action | `Previous step` |
| Next action | `Next step` |
| Reset action | `Reset scenario` |
| Edited status | `Edited` |
| Empty state heading | `Your search workspace` |
| Empty state body | `Choose a scenario, review the query and documents, then start the search.` |
| Placeholder heading | `{Step title} is ready` |
| Placeholder body | `This lesson view will show what the search engine calculates at this step.` |
| Error state | `This scenario could not be loaded. Choose another scenario or reset to the original data.` |
| Reset confirmation title | `Reset edited scenario?` |
| Reset confirmation body | `This will discard your query and document edits and return to the setup step.` |
| Reset confirm action | `Reset scenario` |
| Reset cancel action | `Keep edits` |

Copy rules:

- Use `search engine`, not `algorithm`, when either term would work.
- Keep explanations to two sentences or fewer in Phase 1 placeholders.
- Use active, concrete verbs: `splits`, `counts`, `compares`, `ranks`.
- Never imply that the Phase 1 placeholder has calculated keyword or semantic results.

Destructive actions:

- Dirty reset: requires the alert-dialog confirmation above.
- Scenario switch: discards previous scenario edits immediately by locked decision D-05; no confirmation or warning modal is shown.

## Responsive and Overflow Boundaries

- Phase 1 supports the fixed desktop/projector layout only.
- Do not add tablet stacking, mobile drawers, collapsible panels, or 200% zoom reflow behavior; these are v2 scope.
- At the supported viewport, long document text wraps inside its card.
- Scenario titles and step headings may wrap to two lines; never truncate instructional labels with ellipses.
- Whole-page vertical scrolling is expected when document content grows.

---

## Accessibility Contract

- Every field has a persistent visible label; placeholders are not labels.
- Selection, edited state, active step, disabled boundaries, and progress all have visible text in addition to color.
- Use semantic `header`, `main`, `section`, `nav`, headings, form labels, and buttons.
- The three primary panel regions have accessible names: `Search inputs`, `Lesson steps`, and `Visualization`.
- The reset confirmation uses `AlertDialog`, traps focus while open, and restores focus on close.
- Ensure body text is at least 16px and muted copy remains projector-readable.
- Lucide icons are decorative when adjacent text already supplies the label and use `aria-hidden="true"`.
