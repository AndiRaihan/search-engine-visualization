## Phase Goal

**As a** high school student, **I want to** follow a complete keyword-search lesson from tokenization to explained TF-IDF ranking, **so that** I can explain how each visible calculation changes the result order.

<objective>
Create the single pure keyword snapshot engine that every Phase 2 teaching view consumes, implementing D-01 through D-05, D-08, D-09, and the research-approved duplicate-token policy.

Purpose: Establish one deterministic, unit-tested source of truth so React never recomputes or disagrees about tokenization, matching, TF, IDF, TF-IDF, ranking, or explanations.
Output: Typed keyword snapshot contracts, complete pure calculation helpers, stable canonical snapshot data, and Wave 0 domain-test coverage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-edited text to keyword engine | Query and document textarea values are untrusted strings entering tokenization and arithmetic. |
| Keyword engine to React views | Snapshot strings and numeric values cross into future DOM rendering. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `tokenize`, snapshot text fields | mitigate | Preserve user text only as strings/tokens for normal React rendering; do not produce HTML fragments, event attributes, URLs, or markup strings. |
| T-02-02 | Denial of Service | TF/IDF/TF-IDF snapshot calculation | mitigate | Tokenize each input once per snapshot, use linear passes over the 5-10 document corpus, guard all zero denominators, and assert every emitted numeric value is finite. |
| T-02-03 | Tampering | ranking and explanations | mitigate | Rank from immutable raw score records and generate explanations from the same contribution objects so display text cannot diverge from calculation evidence. |
| T-02-SC | Tampering | npm supply chain | accept | This plan installs or upgrades no packages and uses only existing pinned dependencies. |
</threat_model>
