## Phase Goal

**As a** high school student, **I want to** follow a complete keyword-search lesson from tokenization to explained TF-IDF ranking, **so that** I can explain how each visible calculation changes the result order.

<objective>
Complete the keyword lesson with visible TF-IDF multiplication, document score bars, deterministic ranking, and contribution-based explanations that stay synchronized after edits.

Purpose: Close the teaching loop from visible intermediate values to a trustworthy ranked result whose order and explanation can be reproduced from the screen.
Output: TF-IDF and keyword-ranking views, accessible score bars, edit-driven integration regression, and complete Phase 2 validation evidence.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keyword snapshot to score UI | Raw numeric evidence and user-derived text become tables, result cards, explanations, and progress values. |
| Editable App inputs to ranking result | User changes trigger live recalculation and reordered DOM content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `KeywordRankingStep` explanations/document text | mitigate | Render snapshot strings as normal React text children only; prohibit raw HTML and assert HTML-like edits do not create elements. |
| T-02-02 | Denial of Service | score tables and progress normalization | mitigate | Consume the one shared snapshot, guard maxScore=0, clamp progress to finite 0-100, and never recalculate or resort inside each card. |
| T-02-05 | Repudiation | ranking evidence | mitigate | Show the exact contribution breakdown and score used for every rank so the result can be reproduced from visible evidence. |
| T-02-SC | Tampering | npm supply chain | accept | This plan installs or upgrades no packages and uses the existing pinned Progress/Card/Lucide stack. |
</threat_model>
