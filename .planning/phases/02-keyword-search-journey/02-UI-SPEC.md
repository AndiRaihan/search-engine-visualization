## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Related controls, badge gaps, field label gaps |
| md | 16px | Default spacing, card internals, grid gaps, table cell padding |
| lg | 24px | Section padding, panel padding, page horizontal padding |
| xl | 32px | Layout gaps, major groups within a panel |
| 2xl | 48px | Page header separation, lesson section breaks |
| 3xl | 64px | Page-level spacing (use at most once per view) |

Exceptions:
- Interactive controls (buttons, selects) must have a minimum height of 44px.
- Textareas start at 88px and auto-grow to 160px; after 160px they scroll internally.
- The progress bar track is 8px high.
- Focus rings are 4px wide with a 4px offset.

## Visuals & Focal Points

- **Primary Visual Focal Point**: The Right Panel (`Visualization`) acts as the primary focal point. Whenever the query or document inputs in the Left Panel change, the step-by-step visual calculations update instantly, drawing focus to the computed steps.
- **Visual Hierarchy**: The user's attention is guided sequentially from the input controls (left) to the active step title (top right), then to the main calculation display area (center right), and finally to the next-step button or ranking status.
- **Accessibility**: No icon-only actions are allowed. All icons must be paired with visible text or have descriptive `aria-label` text fallbacks.

## Phase 2 - Step-by-Step Visualization Contract

This section defines the visual representation of search steps inside the Right Panel (`Visualization`). Every step must update instantly as the user types in the Left Panel inputs.

### 1. Tokenization Step (`tokenization`)
- **UI Structure**:
  - Two distinct visual boxes inside a grid or stack:
    1. **Query Tokens**: Shows query text tokenized.
    2. **Document Tokens**: Renders each document card showing its original title/id and its list of normalized tokens.
  - **Token Pill Styling**:
    - Placed inside a rounded badge or capsule pill (`bg-subtle-surface border border-border-custom px-sm py-xs text-body`).
    - Normalized tokens are in lowercase with punctuation split (e.g., `"iphone"` and `"s"` from `"iPhone's"`).
  - **Empty State**:
    - If no tokens can be extracted (e.g. input is empty or contains only punctuation), show a muted text indicator: `"No tokens found"`.

### 2. Word Matching Step (`matching`)
- **UI Structure**:
  - A card container for each document showing:
    - **Header**: Document ID/Title (e.g., `Document 1`).
    - **Match Pill Group**:
      - **Matched Terms**: Rendered as a badge/pill with a solid border, active label text, and a checkmark icon (e.g., `[✓ iphone]`).
      - **Missing Terms**: Rendered as a dashed-border pill with muted text and no checkmark (e.g., `[ the ]`).
    - **Textual Summary Card**:
      - A one-sentence explanation summarizing the match ratio, e.g., `"Matched 1 of 2 terms. Missing: the."`

### 3. Term Frequency Step (`term-frequency`)
- **UI Structure**:
  - A table or grid for each document to show the raw word frequency calculations.
  - **Table Schema**:
    - Columns: `Query Term`, `Count in Doc`, `Total Words in Doc`, `Relative TF`
    - Values: TF is calculated as $\text{TF} = \frac{\text{count}}{\text{total words}}$.
    - Round all decimal values to exactly three decimal places (e.g., `0.250`).
    - Apply tabular numerals (`font-tabular`) to all numeric columns.

### 4. Inverse Document Frequency Step (`inverse-document-frequency`)
- **UI Structure**:
  - A single master table showing the query terms and their collection-wide uniqueness.
  - **Table Schema**:
    - Columns: `Query Term`, `Doc Frequency (df)`, `Total Docs (N)`, `Raw Ratio`, `IDF (ln(N/df))`, `Importance`
    - Math formulas:
      - $\text{IDF} = \ln\left(\frac{N}{\text{df}}\right)$.
      - If $df = 0$, set the IDF score directly to `0.000` to prevent division-by-zero.
      - Round all IDF values to exactly three decimal places (e.g., `1.946`).
  - **Term Strength Badges** (`Importance` column):
    - **Rare (Strong)**: Bold weight text accompanied by a badge with a star icon: `[★ Rare (Strong)]`
    - **Common (Weak)**: Regular/muted weight text with an arrow-down icon: `[⬇ Common (Weak)]`
    - **Deterministic Boundary**: A term is classified as "Rare" if $df \le \lfloor N / 2 \rfloor$ (appears in half or fewer of the documents), otherwise it is classified as "Common".

### 5. TF-IDF Step (`tf-idf`)
- **UI Structure**:
  - For each document, render a card containing a calculation breakdown table.
  - **Table Schema**:
    - Columns: `Query Term`, `TF (Relative)`, `IDF`, `TF-IDF (TF * IDF)`
    - Values:
      - Display the rounded values of TF and IDF.
      - Multiply the raw values and round the resulting TF-IDF product to exactly three decimal places (e.g., `0.487`).

### 6. Keyword Ranking Step (`keyword-ranking`)
- **UI Structure**:
  - Renders the final sorted list of documents descending by keyword score.
  - **Tie-Breaker**: Resolve score ties deterministically using the original document index (e.g., if Document 1 and Document 2 tie, Document 1 ranks above Document 2).
  - **Document Card Content**:
    - **Rank Indicator**: Rendered clearly on the left (e.g. `#1`, `#2`).
    - **Document Title/ID & Score**: Show the total document score (sum of term TF-IDF values, rounded to three decimal places).
    - **Horizontal Score Bar**: An SVG or HTML progress bar showing the document's score relative to the maximum score in the set (e.g., `value={score}`, `max={maxScore}`). Include proper `aria-` labels for screen readers.
    - **Relevance Explanation**:
      - A mathematical breakdown explaining the score composition, e.g.:
        `"Score: 0.450. Term 'iphone' contributed 0.450, 'the' contributed 0.000."`
